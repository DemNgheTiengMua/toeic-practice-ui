## Execution Order

**Defect remediation 1 of 8 — Phase state foundation (prerequisite for d02, d03, d05)**

## What to build

A candidate's active exam phase (skill, unit, group, phase deadline) is taken from the take view the server returns and is only ever changed by a transition response. The wall-clock timer keeps updating the phase progress strip and countdown labels, but it can no longer re-render the candidate back to a different skill or question. Concretely: a candidate who has been moved to Reading stays on Reading across the next timer tick, and reloading the sitting page lands on the question the server says is current.

## Why it broke

The sitting shell currently derives the active phase from wall-clock elapsed time, which contradicts the phase the server has already assigned. Until one representation is authoritative, every other navigation fix can be silently undone by the next timer tick.

## Acceptance criteria

- [ ] The sitting shell seeds `activeSkillId`, `activeUnitNumber`, `activeGroupId` and `phaseDeadlineAt` from the take view and never recomputes them from elapsed time.
- [ ] The 1-second timer tick updates phase progress labels and the remaining countdown only; it does not call question rendering or reassign the active phase.
- [ ] Reloading the sitting page mid-attempt renders the server's current question, not the first question of the exam.
- [ ] A phase served as `activeSkillId = B` while the elapsed clock would still place the candidate in skill A renders skill B after several timer ticks.
- [ ] Service-level test asserts the take view's navigator marks every non-active-skill question locked and the active skill's questions unlocked.
- [ ] Existing practice, placement and CAT unit-lock behaviour is unchanged.
