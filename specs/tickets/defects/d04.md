## Execution Order

**Defect remediation 4 of 8 — Unreachable highlighter and notes**

## What to build

Any element presented to the candidate as annotatable text is genuinely word-tokenized, so selecting text on it reveals the highlighter toolbar. Question stems, cluster stems and the split reading passage all behave the same way, including in listening sections that have no passage at all. Highlighting, note pins and persistence then work in every section the blueprint enables them for.

## Why it broke

Question stems render with the tokenized-text marker but are written as plain text, so the selection handler finds no tokens and bails. Passage-bearing sections work, which is why the defect reads as intermittent.

## Acceptance criteria

- [ ] Selecting words in a question stem reveals the highlighter toolbar.
- [ ] Selecting words in a cluster question stem reveals the highlighter toolbar.
- [ ] Selecting words in a split-screen passage reveals the highlighter toolbar.
- [ ] A listening section with no passage still allows highlighting its question stem.
- [ ] An element only carries the tokenized-text marker if it actually contains word tokens; no container ships with the marker and zero tokens.
- [ ] Highlighting a span, saving a note and reloading the page restores both the highlight and the note pin.
- [ ] Sections whose blueprint forbids highlighting or notes still show no toolbar.
